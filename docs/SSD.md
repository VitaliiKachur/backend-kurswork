# System Specification Document

## 1. Загальна інформація

**Назва проєкту:** ТехОк  
**Тип системи:** вебзастосунок інтернет-магазину електротоварів та техніки  
**Платформа:** PHP MVC, MySQL, HTML/CSS/Bootstrap, JavaScript  
**Базовий шлях застосунку:** `/site`

Система призначена для перегляду каталогу товарів, реєстрації та авторизації клієнтів, роботи з кошиком, оформлення замовлень і адміністрування основних довідників магазину.

## 2. Призначення системи

Система автоматизує основні процеси онлайн-магазину:

- показ категорій та товарів;
- фільтрація товарів за назвою, ціною, наявністю та сортуванням;
- реєстрація, вхід і керування профілем клієнта;
- додавання товарів у кошик, зміна кількості та видалення позицій;
- оформлення замовлення з перевіркою залишків на складі;
- перегляд історії замовлень клієнтом;
- адміністрування товарів, категорій, клієнтів, замовлень і кошика.

## 3. Користувачі системи

| Роль | Опис | Основні можливості |
| --- | --- | --- |
| Гість | Неавторизований відвідувач сайту | Перегляд головної сторінки, категорій, товарів, реєстрація, вхід |
| Клієнт | Авторизований покупець | Робота з кошиком, оформлення замовлення, перегляд профілю та замовлень |
| Адміністратор | Користувач з ознакою `is_admin` | Керування товарами, категоріями, клієнтами та іншими таблицями |

## 4. Функціональні вимоги

### 4.1 Каталог

- Система повинна відображати список категорій.
- Система повинна відображати товари вибраної категорії.
- Система повинна підтримувати пошук за назвою та описом товару.
- Система повинна підтримувати фільтрацію за мінімальною та максимальною ціною.
- Система повинна підтримувати сортування за назвою, ціною та залишком на складі.
- Система повинна відображати детальну сторінку товару.

### 4.2 Обліковий запис клієнта

- Система повинна дозволяти реєстрацію клієнта.
- Система повинна перевіряти унікальність email.
- Система повинна дозволяти авторизацію за email і паролем.
- Система повинна підтримувати вихід із системи.
- Система повинна дозволяти оновлення профілю клієнта.
- Система повинна дозволяти завантаження фото профілю.

### 4.3 Кошик

- Система повинна дозволяти авторизованому клієнту додавати товар у кошик.
- Система повинна перевіряти, що кількість у кошику не перевищує залишок товару.
- Система повинна дозволяти змінювати кількість товару в кошику.
- Система повинна дозволяти видаляти товар із кошика.
- Система повинна повертати актуальну кількість товарів у кошику.
- Система повинна розраховувати загальну суму кошика.

### 4.4 Замовлення

- Система повинна дозволяти оформити замовлення тільки авторизованому клієнту.
- Система повинна забороняти оформлення порожнього кошика.
- Система повинна повторно перевіряти залишки товарів перед створенням замовлення.
- Система повинна створювати запис замовлення та позиції замовлення в транзакції.
- Система повинна зменшувати залишки товарів після успішного оформлення.
- Система повинна очищати кошик після створення замовлення.

### 4.5 Адміністрування

- Система повинна дозволяти доступ до адмін-панелі тільки адміністраторам.
- Адміністратор повинен мати можливість переглядати таблиці `customers`, `products`, `categories`, `orders`, `order_items`, `cart`.
- Адміністратор повинен мати можливість створювати записи товарів, категорій і клієнтів.
- Адміністратор повинен мати можливість оновлювати та видаляти записи.
- Система повинна забороняти видалення товару, якщо він використовується в замовленнях.

## 5. Нефункціональні вимоги

| Категорія | Вимога |
| --- | --- |
| Безпека | Доступ до кошика, профілю, замовлень і адмін-панелі має перевірятися через сесію користувача. |
| Надійність | Створення замовлення має виконуватися в транзакції бази даних. |
| Продуктивність | Основні сторінки каталогу повинні завантажуватися без надмірних запитів до БД. |
| Сумісність | Система повинна працювати в сучасних браузерах і локальному середовищі WAMP. |
| Зручність | Інтерфейс має підтримувати навігацію між головною сторінкою, категоріями, кошиком і профілем. |
| Підтримуваність | Код розділено на `controllers`, `models`, `views`, `core`, `config`. |

## 6. Архітектура системи

Проєкт реалізовано за MVC-підходом:

- `index.php` - точка входу;
- `autoload.php` - автозавантаження класів;
- `config/routes.php` - таблиця маршрутів;
- `controllers/` - обробка HTTP-запитів;
- `models/` - доступ до даних і бізнес-операції;
- `views/` - HTML/PHP-шаблони сторінок;
- `core/` - базова інфраструктура: контролер, модель, маршрутизатор, сесії, БД, шаблонізатор;
- `assets/` - стилі, зображення товарів, категорій і профілів.

## 7. Основні маршрути

| Метод | Маршрут | Призначення |
| --- | --- | --- |
| GET | `/site/` | Головна сторінка |
| GET | `/site/category` | Список категорій |
| GET | `/site/product/view?category_id={id}` | Товари категорії з фільтрами |
| GET | `/site/product/detail?id={id}` | Детальна сторінка товару |
| GET/POST | `/site/profile/login` | Вхід користувача |
| GET/POST | `/site/profile/register` | Реєстрація користувача |
| GET | `/site/profile/check-email?email={email}` | Перевірка email |
| GET | `/site/cart` | Перегляд кошика |
| GET | `/site/cart/add?product_id={id}&quantity={qty}` | Додавання товару в кошик |
| GET | `/site/cart/update?item_id={id}&quantity={qty}` | Оновлення кількості |
| GET | `/site/cart/remove?item_id={id}` | Видалення з кошика |
| GET/POST | `/site/cart/checkout` | Оформлення замовлення |
| GET | `/site/profile/orders` | Історія замовлень |
| GET/POST | `/site/admin` | Адмін-панель |

## 8. Дані та сутності

| Сутність | Таблиця | Основні поля |
| --- | --- | --- |
| Клієнт | `customers` | `CustomerID`, `FirstName`, `LastName`, `Email`, `Password`, `Phone`, `AddressClient`, `City`, `ProfilePhoto`, `is_admin` |

| Позиція замовлення | `order_items` | `OrderItemID`, `OrderID`, `ProductID`, `Quantity`, `Price` |

## 9. Інтеграційні точки

Система має внутрішні JSON-ендпоінти, які використовуються JavaScript-кодом сторінок:

- `/site/cart/add` - додавання товару в кошик;
- `/site/cart/count` - отримання кількості товарів у кошику;
- `/site/cart/update` - оновлення кількості товару;
- `/site/cart/remove` - видалення товару з кошика;
- `/site/profile/check-email` - перевірка зайнятості email.

Опис двох endpoint-ів наведено у файлах:

- `docs/openapi.yaml`;
- `docs/postman_collection.json`.

## 10. Обмеження та припущення

- Проєкт розрахований на запуск у локальному середовищі WAMP.
- Базовий URL у документації: `http://localhost/site`.
- Для операцій з кошиком потрібна активна сесія авторизованого клієнта.
- API використовує cookie-based session authentication.
- Паролі в поточній реалізації порівнюються за значенням із БД; для production-версії потрібно використовувати хешування паролів.
